# コードリファクタリング計画

作成日時: 2025-08-12 17:00
参照アイディアファイル: `002_コードの修正.md`

## 実装する機能

コードの可読性向上とデバッグ環境整備のためのリファクタリング

## 機能の詳細な仕様

### 1. ワイルドカードインポートの除去

現在のコードで使用されている `use *` パターンを具体的なインポートに変更する：

- `src/mcp/tools/mod.rs`: `pub use save_markdown::*;`
- `src/vault/mod.rs`: `pub use operations::*;`
- テスト内での `use super::*;`

### 2. デバッグ環境の構築

- デバッグ専用の vault 設定機能を実装
- デバッグ関連の処理を `src/debug.rs` に集約
- 本番環境とデバッグ環境の分離

### 3. デバッグ機能の仕様

#### デバッグモードの切り替え方法

- コマンドライン引数による切り替えのみ
- `--debug` フラグの追加
- `obsidian-mcp-server --debug`

#### デバッグ機能の内容

- デバッグ時はハードコードされた専用 vault (`./debug-vault/`) を使用
- デバッグ用の追加ログ出力（トレースレベル）
- テスト用のダミーデータ生成機能
- 全てのデバッグ関連処理は `src/debug.rs` に集約

#### MCP 設定変更のイメージ

**通常モード（本番環境）:**

```json
{
  "mcpServers": {
    "obsidian-mcp-server": {
      "command": "obsidian-mcp-server",
      "args": ["--vault-path", "/path/to/production/vault"]
    }
  }
}
```

**デバッグモード:**

```json
{
  "mcpServers": {
    "obsidian-mcp-server": {
      "command": "obsidian-mcp-server",
      "args": ["--debug"]
    }
  }
}
```

**設定変更のポイント:**

- `--vault-path` は不要（`./debug-vault/` が自動使用される）
- `--debug` フラグを追加するだけで切り替え完了
- GitHub Copilot から簡単にデバッグモードを利用可能

## 技術的な実装方針

### Phase 1: ワイルドカードインポートの修正

1. 各ファイルでワイルドカードインポートを特定
2. 実際に使用されている型・関数を明示的にインポート
3. 未使用のインポートを削除
4. ビルドとテストで動作確認

### Phase 2: デバッグモジュールの実装

1. `src/debug.rs` ファイルを作成
2. デバッグ用設定構造体の定義
3. コマンドライン引数 `--debug` の処理実装
4. ハードコードされたデバッグ vault パスの設定
   - `./debug-vault/` を固定パスとして使用
   - デバッグ用ディレクトリの自動作成機能

### Phase 3: 既存コードの統合

1. `main.rs` でのデバッグモードの初期化
2. `config.rs` でのデバッグ設定の統合
3. `vault/operations.rs` でのデバッグ対応
4. テストでの動作確認
