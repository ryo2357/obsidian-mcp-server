# ロガー実装報告書

作成日時: 2025-08-14 15:25

## 実装内容の概要

MCP サーバーが標準入出力 (stdin/stdout) をプロトコル通信専用で利用する設計上の制約に対応するため、ファイルベースのロギング機能を新規実装した。運用時とデバッグ時の双方で一貫したログ取得が可能となり、問題解析と動作追跡の信頼性を向上した。

## 実装結果の詳細

### 1. ロギング基盤の導入

- `flexi_logger` + `log` クレートを採用
- 詳細フォーマット (`flexi_logger::detailed_format`) を利用
- サイズローテーション (10MB) と最新 5 ファイル保持ポリシーを設定
- ログファイル命名にタイムスタンプ付与 (`Naming::Timestamps`)

### 2. 出力ディレクトリ戦略

| モード   | 出力ディレクトリ                         | 例                    |
| -------- | ---------------------------------------- | --------------------- |
| 通常     | `<config_dir>/obsidian-mcp-server/logs/` | `%APPDATA%/.../logs/` |
| デバッグ | `./.config/logs/`                        | プロジェクト直下      |

### 3. 初期化フロー

- `main.rs` に `APP_DIR` (once_cell + dirs) を追加
- モード判定後に `logger::init_logger(level, path)` を実行
- 以降 `debug!` などのマクロでログ記録

### 4. DebugConfig の拡張

- `vault_path` → `vault_dir` へ名称統一
- `config_dir` フィールドを追加し `.config/logs` を保持
- デバッグ時の設定・ログ出力を分離管理

### 5. Config の調整

- `vault_path` → `vault_dir` にリネーム
- `load_or_default` のインターフェースを `PathBuf` 受け取りに簡素化
- 呼び出し側で構成ルート決定し責務分離

### 6. main.rs の変更

- CLI オプション `--vault-path` を `--vault-dir` に変更
- 通常/デバッグで異なるログ初期化ロジックを実装
- デバッグ処理の標準出力 `println!` を `debug!` ログへ移行

## 実装された主要ファイル

1. `src/logger.rs` : ロガー初期化関数 `init_logger`
2. `src/main.rs` : ロガー導入、APP_DIR 追加、起動時初期化
3. `src/debug.rs` : ディレクトリフィールドと命名の統一
4. `src/config.rs` : フィールドリネームと API 簡素化
5. `Cargo.toml` : 依存追加 (`flexi_logger`, `log`, `once_cell`)

## 技術的成果

- 標準入出力汚染の根本的排除
- ログローテーションによるディスク使用量制御
- モード毎の出力分離でデバッグ/運用混在を防止
- 一貫した命名 (`vault_dir`) による可読性向上

## リスクと対応

| リスク     | 内容                                 | 対応                                                          |
| ---------- | ------------------------------------ | ------------------------------------------------------------- |
| 権限エラー | 通常モードでログディレクトリ作成失敗 | OS 標準 config ディレクトリ利用、失敗時は早期エラー化検討余地 |
| ログ肥大   | 長期運用でログ蓄積                   | サイズローテーション + 5 世代保持で軽減                       |
| CLI 互換性 | `--vault-path` 変更                  | ドキュメント更新済み、必要なら別名引数追加を今後検討          |

## テスト / 動作確認

- デバッグモード起動: ログディレクトリ生成とファイル出力確認
- 通常モード起動: APP_DIR 配下に `logs/` 生成を確認
- 既存 MCP 機能（initialize, tools/list, tools/call）の正常動作を確認

## 今後の改善提案

1. ログレベルを CLI オプション化（例: `--log-level`）
2. JSON 形式ログ対応（機械処理向け）
3. エラーログとアクセスログの分離
4. 起動設定を TOML による外部化（ローテーション閾値等）

## まとめ

MCP の標準入出力専有要件に即した安全なロギング基盤を導入し、運用・開発双方の可観測性を向上させた。今後はロギング設定の外部化と可観測性機能（メトリクス等）の拡張を行う余地がある。
